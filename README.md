# НейроДело — PHP / MySQL

Сайт услуг и CRM для обычного PHP-хостинга. VPS, Python, Composer, Node.js и постоянно работающий процесс не нужны. PHP 8.1–8.5; расширения PDO, pdo_mysql, mbstring; MySQL 5.7/8 или совместимая MariaDB; Apache с .htaccess. Рекомендуется PHP 8.4 или 8.5.

## Установка на SpaceWeb

1. Добавьте домен `neurodelo.pro` к сайту в панели sweb. Выберите PHP 8.4 (или 8.5), включите HTTPS-сертификат и перенаправление HTTP → HTTPS. Проверьте наличие PDO MySQL и mbstring в настройках PHP.
2. Создайте базу MySQL и пользователя в панели. Сохраните имя базы, пользователя, пароль и **точный адрес сервера MySQL из панели** — он может отличаться от `localhost`.
3. Через phpMyAdmin выберите созданную базу и импортируйте `database/schema.sql`. Скрипт создаёт таблицы `nd_*`, не удаляя существующие данные. Не импортируйте его в чужую рабочую базу.
4. Загрузите **содержимое** папки `public/` в корневую папку сайта (часто `public_html`, точное имя смотрите в панели), включая скрытый файл `.htaccess`. Саму папку `private/` разместите **рядом с корневой папкой, на один уровень выше**, а не внутри неё. Пример:

   ```text
   папка-домена/
     private/
       app.php
       config.php
       .htaccess
     public_html/          ← корень сайта
       index.php
       index.html
       api.php
       studio.php
       setup.php
       .htaccess
       ... CSS, JS и crm.html
   ```

   PHP использует путь `dirname(__DIR__)/private/app.php`. Если структура sweb отличается, сначала согласуйте корень сайта/расположение папок. **Не размещайте весь архив в публичной папке**: конфигурация базы должна оставаться вне доступа из браузера. Папки `database`, `tests`, инструкции и Git на сайт загружать не нужно.
5. В `private/` скопируйте `config.example.php` в `config.php`. Заполните реквизиты базы, `app_url` = `https://neurodelo.pro` (без завершающего слеша). Для первого запуска задайте отдельный случайный `setup_key` длиной от 32 символов, например сгенерированный менеджером паролей. Не используйте пароль CRM или базы в качестве ключа. Файл содержит секреты: редактируйте через защищённую панель/SFTP, не отправляйте в чат и не добавляйте в Git. Ограничьте доступ средствами хостинга.
6. Откройте **https://neurodelo.pro/setup.php**. Введите ключ установки и придумайте пароль CRM длиной минимум 12 символов (до 72 байт). Страница сохранит только хеш пароля и направит в кабинет.
7. Удалите `setup.php` с сервера и очистите `setup_key` в `private/config.php`. Повторная установка также блокируется записью администратора в БД; установленный пароль через setup.php заменить нельзя.
8. Завершите настройку документов по разделу «Согласие и документы» ниже. До этого форма отключена. Затем откройте сайт, отправьте тестовую заявку, войдите через значок ◈ в подвале и проверьте заявку, статус, заметку и выход. Проверка на реальном sweb ещё не выполнена — требуется доступ владельца к хостингу. При ошибке 500 проверьте PHP/расширения и журнал ошибок панели; при ошибке 503 API проверьте конфигурацию, подключение к MySQL и импорт таблиц.

В архиве для загрузки папка `public/` называется `public_html/` для наглядности; фактический корень определяется в панели.

## Возможности и защита

- Форма сохраняет заявки в MySQL. Сообщения, отправленные только в Telegram @minden2006, автоматически не импортируются.
- CRM: контакты, задача, поиск, фильтр по статусу, заметки, следующий шаг, счётчики.
- Вход `/studio.php` или значок ◈. Малозаметная ссылка не заменяет пароль.
- Сервер проверяет авторизацию при чтении/редактировании. Пароль хешируется через PHP password_hash/password_verify, запросы к базе параметризованы.
- Сессии на 8 часов, случайные токены (в базе только хеш), cookie HttpOnly / SameSite=Strict / Secure на HTTPS; CSRF при изменениях, проверка Origin, ограничение попыток входа, установки и заявок.
- Клиентские данные выводятся через textContent. Не возвращаются браузеру пароли, SQL-ошибки и конфигурация.
- Хостинг должен передавать PATCH-запросы PHP (используются для редактирования). Проверяется тестовой правкой в кабинете. Роутинг /api.php?r=… работает без mod_rewrite.
- Перед первыми настоящими клиентами укажите владельца/оператора данных, опубликуйте политику обработки персональных данных и проверьте требования к согласию, хранению и удалению. Уведомление в форме предварительное.
- Настройте резервное копирование MySQL в панели. Бэкапы и конфигурацию храните вне публичной папки. Восстановление пароля — через владельца хостинга, отдельной публичной формы нет.

## Локальный запуск и проверки разработчика

Создайте отдельную тестовую базу, импортируйте schema.sql. Для ручной разработки можно создать `private/config.php` с `app_url=http://127.0.0.1:8000` (только локально), затем:

```sh
php -S 127.0.0.1:8000 -t public tests/router.php
```

Синтаксическая проверка PHP:

```sh
find public private tests -name '*.php' -exec php -l {} \;
```

Интеграционная регрессия: `tests/test_prelaunch.py` (старый `check_php.py` теперь совместимый вход в эту же регрессию). Нужны Python, requests, Playwright/Chromium, PHP и **локальная тестовая MySQL/MariaDB**, чья тестовая учётная запись может создавать и удалять только тестовые БД. Не используйте реквизиты настоящего хостинга. Тест принимает DSN только с host=127.0.0.1 и port, без имени БД; создаёт случайную БД `neuro_test_*`, копирует приложение в временную папку, а после удаляет только свою базу/копию. Рабочий config.php не меняется.

```sh
node --test tests/api-client.test.cjs
# Укажите реквизиты только локального одноразового тестового сервера:
NEURO_TEST_DSN='mysql:host=127.0.0.1;port=3306' NEURO_TEST_USER=test_admin python3 -m unittest discover -s tests -p test_prelaunch.py -v
```

Пароль тестового сервера — через NEURO_TEST_PASSWORD; не вставляйте настоящий пароль в историю команд. PHP_BIN и CHROMIUM_BIN позволяют выбрать уже установленные бинарные файлы. Не запускайте прежнюю инструкцию импорта схемы в настоящую базу ради тестов.

Проверяются подтверждённое сохранение, конфликт версий, контактные данные, идемпотентность, CSRF/401, понятные ошибки и журналы, истечение входа/черновик, политика и согласие, потеря ответа сервера, безопасный повтор и миграции исторических записей. Тестовая политика является синтетической фикстурой и не включается в сайт.

Старая Python/SQLite-версия заменена. Автоматический перенос существующей SQLite-базы не включён; если она уже использовалась для настоящих заявок, сохраните резервную копию и выполните отдельный перенос до переключения.


## Обновление существующей PHP-версии (без автоматического развёртывания)

1. До любых изменений сделайте резервную копию базы и файлов и проверьте возможность восстановления. Поставьте сайт в режим обслуживания, исключив одновременную работу старых и новых JS/PHP-файлов.
2. Изучите текущие столбцы `nd_leads`. Если это исходная версия из предыдущего архива, примените **по одному и один раз**, в порядке: `database/migrations/001_lead_versions.sql`, `002_idempotency.sql`, `003_consent.sql`. На новой установке импортируется только свежий `schema.sql`, миграции поверх него запускать не нужно. MySQL DDL не гарантирует откат всей цепочки: проверяйте каждый шаг и не повторяйте уже применённый ALTER.
3. Миграции добавляют столбцы и уникальный индекс, не удаляют лиды. У исторических строк версия становится 1, а согласие/ключ запроса остаются NULL: прежним клиентам согласие не приписывается.
4. Обновите public/ и private/app.php совместно, очистите кэш браузера/хостинга. Существующий private/config.php **не заменяйте примером**: дополните только настройками документов. Хеш пароля и существующие сессии сохраняются.
5. Выполните контрольный сценарий на тестовой копии хостинга; лишь после отдельного решения владельца переключайте реальный сайт. На sweb/MySQL 8 текущая версия ещё не проверена.

## Согласие и документы (требуются решения владельца)

Юридический текст в коде не придумывался. По умолчанию приём заявок закрыт: отсутствуют утверждённая политика и параметры её версии.

До включения формы владелец должен утвердить документы и точную формулировку согласия с учётом своего статуса и применимых требований: сведения об операторе, цели/основания обработки, состав данных, место и сроки хранения, порядок отзыва/удаления, доступ третьих лиц (хостинг, Telegram), необходимость отдельного документа согласия и уведомлений. Текст флажка предварительный, требует юридической проверки; код не является подтверждением соответствия законодательству.

После проверки:

- Сохраните **утверждённый текст** в `private/privacy-policy.txt` (UTF-8, простой текст). Файл отдаётся только через `/privacy.php`, с HTML-экранированием.
- В существующем `private/config.php` добавьте `privacy_policy_approved => true` и `privacy_policy_version => '2026-10-21-v1'` (пример идентификатора, не фиктивная дата утверждения). Реальная версия должна соответствовать утверждённому документу.
- При каждом изменении текста присваивайте новую версию. Храните предыдущие утверждённые версии в закрытом архиве владельца: в заявке фиксируются версия и SHA-256 текста, но сами исторические документы автоматически не архивируются.
- Проверьте текст предварительного флажка и приведите его в точное соответствие утверждённым документам. Если нужны отдельные документы/согласия, их должен определить владелец с юристом до запуска.

Флажок не выбран автоматически. Сервер требует boolean true и актуальную версию, записывает consent, серверное UTC-время consent_at, policy_version, policy_hash вместе с лидом одним INSERT. Чтение этих полей доступно только авторизованному владельцу; PATCH не изменяет их. Отправка без утверждённых документов отключена на сервере независимо от JS. Telegram остаётся отдельной ссылкой; его обработку данных также необходимо оценить.

## Ограничения восстановления и повторов

Ключ отправки сохраняется при сетевой ошибке/таймауте в памяти текущей вкладки, пока поля не изменены. Повтор того же запроса не создаёт второй лид. Новая успешно отправленная или изменённая заявка получает другой ключ. После закрытия/перезагрузки вкладки память и черновики теряются; персональные данные намеренно не сохраняются в localStorage. Автоматического объединения клиентов по email/телефону нет.

При конфликте версии CRM оставляет введённые поля и предлагает загрузить актуальные данные; замена локальных правок требует явного подтверждения. При истечении входа черновик восстанавливается после повторного входа в той же вкладке. Автоматического повторного сохранения нет; новая попытка проходит серверную проверку версии.

Сервер журналирует идентификатор ошибки, класс, basename файла, номер строки и SQLSTATE, не текст SQL, параметры, пароли или HTTP-body. Настройте PHP display_errors=Off и error_log вне публичной папки с доступом только владельца/хостинга. В интерфейсе выводятся заранее определённые русские сообщения.
