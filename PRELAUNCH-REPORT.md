Файлы: public/api-client.js (новый общий клиент), public/script.js, public/index.html, public/api.php; тест tests/api-client.test.cjs.

Клиент требует ожидаемый HTTP 201, application/json, корректный JSON, ok === true и положительный целочисленный lead_id. PHP выдаёт результат только после успешного INSERT (или подтверждённого идемпотентного повтора) в MySQL. При HTML, неверном статусе, постороннем JSON и ошибке данные формы не сбрасываются.

Запущено: 9 начальных регрессий Node (включая успешный ответ и 8 ошибочных вариантов); PHP lint, JS syntax; интеграционный SELECT по возвращённому id подтвердил реальную запись. После следующих исправлений эти тесты повторены в общей регрессии. Итог: PASS. На sweb не проверено.

## 2. Конкурентное редактирование

Файлы: public/api.php, public/crm.js, public/crm.html, database/schema.sql, database/migrations/001_lead_versions.sql, tests/test_prelaunch.py.

Вводится version. Единственный UPDATE меняет запись только WHERE id=? AND version=? и атомарно увеличивает версию. Если версия устарела — 409; неизвестный id — 404. Интерфейс оставляет локальный текст и предлагает загрузить актуальную версию. Замена локальных несохранённых правок требует явного подтверждения. Новые серверные данные не перезаписываются автоматически.

Запущено: тест двух сессий с одной исходной версией; первая запись сохранена, вторая отклонена, SELECT подтвердил сохранность первого текста. После загрузки версии 2 следующая правка проходит. Отсутствующая версия даёт 422, отсутствие CSRF — 403. В браузере воспроизведён конфликт и подтверждённая загрузка актуальных данных. PHP/JS проверки прошли. Итог: PASS. Миграция существующей установки требует отдельного выполнения после бэкапа; никаких миграций на хостинге не запускалось.

## 3. Контакты и дубли

Файлы: private/app.php, public/api.php, public/script.js, public/index.html, database/schema.sql, database/migrations/002_idempotency.sql, tests/test_prelaunch.py.

Сервер проверяет email, Telegram @username длиной 5–32 и телефон РФ (+7 или национальная 8, 10 последующих цифр и российский код). Зарубежные телефонные регионы не заявлены. Поле принимает один способ связи, которого достаточно. Услуга проверяется по списку. На запрос создаётся случайный 256-битный ключ, уникальный индекс обеспечивает идемпотентность даже при повторном INSERT; хеш содержимого запрещает использовать тот же ключ для другой заявки. Повтор принятого запроса возвращает прежний id; новая легитимная заявка с новым ключом не объединяется с предыдущей. Кнопка и программная повторная отправка блокируются, пока идёт запрос.

Запущено: валидные email/Telegram/+7/8, некорректные контакты, короткий username, неподдерживаемый +1 и ошибочный +8; неверная услуга; повтор ключа, конфликт содержимого, новый запрос с тем же контактом. Браузерный сценарий: реальный INSERT → искусственная потеря успешного ответа → повтор → тот же id/одна строка БД. Два requestSubmit подряд дали один запрос. PHP/JS проверки прошли. Итог: PASS. Ключ и черновик живут в памяти вкладки; закрытие/перезагрузка их сбрасывает, автоматического объединения по контакту нет.

## 4. Ошибки, таймауты и черновики

Файлы: public/api-client.js, public/crm.js, public/crm.html, public/script.js, private/app.php, public/api.php; тесты tests/api-client.test.cjs и tests/test_prelaunch.py.

Общий клиент проверяет ответы и даёт заранее заданные русские сообщения по статусу/коду. Серверные detail и технические исключения напрямую пользователю не показываются. AbortController ограничивает весь запрос (включая чтение тела) 15 секундами. Сетевые ошибки, HTML, повреждённый JSON и 4xx/5xx обрабатываются. После истечения входа черновик диалога остаётся в памяти и восстанавливается после повторного входа, без автоматического сохранения. Конфликт при повторе правок обрабатывается версией.

Сервер пишет только безопасные диагностические метаданные: id, класс исключения, basename/строка, SQLSTATE. Пароли, запросы SQL, параметры, тела запросов и полные пути не журналируются этим обработчиком. Клиент получает общий 503 и X-Request-ID. Фактическое расположение/права PHP-журнала необходимо настроить на хостинге.

Запущено: Node-сценарии скрытия внутреннего текста, сети и таймаута; браузер 401 при сохранении → повторный вход → восстановленный черновик → HTML 503 без раскрытия → успешный безопасный повтор; 400 JSON/415 Content-Type; настоящая ошибка подключения к специально отсутствующей тестовой БД дала 503, идентификатор и запись диагностических метаданных. PHP/JS проверки прошли. Итог: PASS. При закрытии вкладки черновик не сохраняется; общей персистентной очереди офлайн-правок нет.

## 5. Техническое согласие

Файлы: public/index.html, public/script.js, public/styles.css, public/privacy.php (новый), public/api.php, private/app.php, private/config.example.php, public/crm.html, public/crm.js, database/schema.sql, database/migrations/003_consent.sql, tests/router.php, tests/test_prelaunch.py.

Добавлен непредвыбранный обязательный флажок и ссылка на /privacy.php. Для включения формы нужны одобренный владельцем private/privacy-policy.txt, privacy_policy_approved=true и непустая версия. До этого форма и серверный приём выключены. Юридического текста в проект не добавлено; тест использует только синтетическую фикстуру во временной копии.

Сервер требует строго boolean true и актуальную версию. В той же записи/INSERT сохраняются consent=1, серверное время UTC consent_at, версия и SHA-256 фактического текста. Неавторизованный доступ к списку лидов закрыт, обычный PATCH не меняет данные согласия. Историческим записям согласие не приписывается: NULL. При смене версии флажок сбрасывается, текст заявки сохраняется.

Запущено: false/null/строка/число вместо согласия → 422; старая версия → 409; действующее согласие → реальная запись, проверены время/версия/hash; без авторизации → 401; снятие одобрения → закрытая форма/API и privacy.php 503; браузер без флажка не отправляет, после успеха он не выбран, при смене версии сбрасывается без потери текста. PHP/JS проверки прошли. Итог технической части: PASS.

Остаётся решение владельца/юриста: оператор и его реквизиты, основания/цели, состав данных, сроки/место хранения, отзыв/удаление, третьи лица, необходимость отдельного согласия/документов и утверждённая формулировка checkbox. Исторические версии документов нужно архивировать владельцу; система сохраняет версию/hash, а не архив текста. Юридическое соответствие не заявляется. До завершения этих решений приём заявок остаётся закрытым.
