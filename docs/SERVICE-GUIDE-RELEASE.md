# Услуги и подготовка брифа — первый функциональный выпуск

Статус перед публикацией: READY_FOR_INTEGRATION. Production проверяется отдельно;
успешные локальные тесты не означают публикацию.

## Работающая функция

`/services.php`: четыре направления (лендинг, сайт, ИИ/автоматизация,
веб-приложение), описание результата и вопросов для обсуждения. Посетитель
выбирает направление и функции, описывает задачу и получает редактируемый
исходный бриф в полях формы и готовый текст для копирования/отправки в Telegram.
Важные ограничения, цена и сроки согласуются отдельно; коммерческих обещаний нет.

Подготовка выполняется только в браузере. Нет API отправки брифа, БД,
localStorage, фоновой отправки, аналитики или включения приёма лидов.
Передача текста Telegram происходит только при явном открытии пользователем
ссылки; само сообщение пользователь проверяет и отправляет самостоятельно.
Автоматическое копирование имеет fallback ручного выделения. Изменения формы
скрывают старый результат. Без JavaScript доступны описания и реальный контакт.

Меню и карточки главной ведут на страницу с выбранным направлением.
Сохраняются прежний дизайн, Telegram @minden2006, форма с fail-closed privacy
и существующий вход владельца. CRM/платежи/платный AI в выпуск не включены.

## Исправление доставки

Проверенные general-purpose исправления из draft-интеграции перенесены на main
без новых CRM-зависимостей. Релиз содержит 18 явных app paths, включая
`public/services/` и `private/services/`; их точный состав проверяется также PHP
агентом. Полнота дерева, SHA-256, запрет traversal и симлинков предков,
создание вложенных каталогов, сохранение config/uploads и guarded rollback
проверены в изоляции. Каждый CSS/JS из manifest проверяется после выпуска.
Пустая migration policy сохраняется: этому выпуску не нужны изменения БД.
Workflows и existing GitHub-to-SpaceWeb architecture не менялись.

Preflight дополнен только read-only metadata: nd_* table names, migration journal
версии/состояния/checksums, MySQL version и SHA-256 schema metadata. Клиентские
строки, реальные credentials, SQL dumps и config contents не экспортируются.
Это даёт фактическую основу следующему CRM milestone через штатный secure SSH
pipeline, без поручения владельцу выполнять SQL или искать логи.

## Выполненные проверки

PHP8.4/MySQL5.7/Apache2.4/Chromium, изолированные loopback fixtures:

- 133 Python tests PASS, включая 6 browser/HTTP tests страницы и 10 новых
  package completeness/nested path tests; 51 release tests входят в этот набор.
- Node API client: 12 PASS.
- PHP syntax: 13 files PASS; JS syntax: 4 files PASS (включая nested asset).
- Release policy, compileall, actionlint, git diff --check PASS.
- Gitleaks текущего дерева: утечек не обнаружено.
- Страница отдельно работает без private/config.php и без подключения к БД.
- Mobile375px, переносы/нет горизонтального overflow, clipboard rejection,
  no-JS fallback, неизвестный service query, текст вместо HTML, отсутствие
  фоновых запросов, сброс устаревшего результата PASS.

После публикации обязательны exact SHA/hash evidence и реальный Chromium
smoke `/services.php`: выбрать направление → подготовить бриф → проверить текст
и URL Telegram без отправки сообщения. Проверить также неизменность privacy,
доступность главной и security baseline. Только затем DEPLOYED_AND_VERIFIED.

операторов/DDL каждого шага и безопасная identity-bound инициализация owner.

пароль администратора не придумывается, existing secret не заменяется.
Недоступность owner setup не блокирует эту независимую публичную страницу.
