# Stage 11 — проверка владельцем

Проверяйте на согласованном тестовом сайте с тестовыми клиентами. Эти пути относятся к коду ветки Stage11; они не означают, что production neurodelo.pro обновлён. Сейчас полный запуск NOT_READY.

- [ ] На `/` открываются «Что создаём», «Как работаем», «Вопросы» и форма «Обсудить идею». Кабинет клиента — ссылка внизу. Отдельного рабочего каталога и интерактивного брифа пока нет.
- [ ] Если тестовая политика опубликована и одобрена, согласие в форме доступно и изначально снято. После заполнения и согласия заявка появляется в `/studio.php` и `/workspace.php#leads`. При ошибке остаётся текст, повтор запроса не создаёт вторую заявку. На production политику ради теста не включать.
- [ ] `/customer.php?view=register` — тестовая регистрация. Подтвердите адрес через тестовое письмо, войдите/выйдите, проверьте восстановление. Письма настоящим клиентам не отправлять.
- [ ] В `/workspace.php#customers` клиент соответствует заявке; `/workspace.php#deals` показывает историю сделки; создание заказа не дублируется.
- [ ] `/ai.php?mode=owner#rates` и `#quotes` используйте согласно фактическим вкладкам ИИ-центра: проверьте источники ставок, неизвестные расходы, расчёт и отдельное точное одобрение цены. ИИ не должен утверждать цену сам. Если флаг отключён — раздел недоступен, это ожидаемо.
- [ ] В `/workspace.php#orders`, `#projects`, `#tasks` связи и этапы отражают реальные изменения. Не создавать сотрудников: вы работаете как владелец.
- [ ] `/portal.php#orders` и `#projects` под тестовым клиентом показывают только его записи. Список заявок до заказа пока не реализован.
- [ ] `/collaboration.php?mode=owner` и `/collaboration.php` — сообщение, допустимый тестовый файл, редакция документа, запрос изменений и повторное согласование. Старые редакции остаются, чужой клиент файл не видит.
- [ ] `/billing.php?mode=owner` и `/billing.php` — суммы/статусы тестового счёта. Sandbox/mock пометка не должна восприниматься как реальные поступившие деньги. Настоящую оплату/возврат не выполнять.
- [ ] `/handoff.php#new`: выберите номера реального тестового проекта, открытой задачи и текущей принятой редакции ТЗ. Нажмите «Подготовить задание». Прочитайте текст, удалите/не переносите персональные данные или секреты без разрешения. Нажмите «Скопировать задание», вручную отправьте его в свою среду Codex.
- [ ] Верните JSON с `files` и `requirements` через «Загрузить результат». Код не запускается. «Отправить на проверку» показывает реальные статические проверки и недоступные технические проверки. Результат с непроверенным кодом должен оставаться заблокированным.
- [ ] Для корректных документов нажмите «Утвердить результат» только после чтения и проверки точной редакции. Клиент ещё не должен видеть результат. «Передать клиенту» — отдельное подтверждение. Затем проверьте приёмку в существующем разделе результатов Stage6. Несогласованный результат передать нельзя.
- [ ] «Запросить доработку» сохраняет комментарий и старую редакцию. Новый результат проверяется и одобряется заново. Изменение ТЗ требует нового задания.
- [ ] На телефоне открываются «Разделы CRM/кабинета», формы читаются без горизонтального скролла; недоступный каталог не выдаётся за рабочий.

Перед production отдельно нужны review зависимых PR, Stage9 либо согласованное ограничение продукта, утверждённые privacy/retention документы, проверенные письмо/оплата (если включаются), одобренные миграции/backup/пакет/rollback и hosting verification. Никаких новых Codex API-ключей для этого ручного маршрута не требуется.
