# Stage 2.1: защита резервных файлов и безопасная обработка политики

Резервные файлы с тильдой и распространёнными расширениями копий обходили Apache-запреты. Нечитаемый файл утверждённой политики приводил к TypeError в PHP 8.4. Изменения закрывают эти случаи, сохраняют внешний вид сайта, API-контракт и блокировку приёма заявок до утверждения документов.

## Изменения

- public/.htaccess: запрет редакторских копий и временных файлов; прежние ограничения сохранены.
- private/app.php и public/privacy.php: безопасное чтение политики и единый проверенный снимок текста, enabled=false при недоступном документе.
- scripts/diagnose.php: CLI-only диагностика без записи данных и вывода секретов.
- tests/test_apache_security.py: реальные HTTP-проверки на локальном Apache.
- tests/test_prelaunch.py: дополнительные изолированные проверки политики, конфигурационных ошибок, диагностики, установки и авторизации.
- docs/STAGE-2.1-REPORT.md: результаты этапа и ограничения production-проверки.
- docs/STAGE-2.1-GITHUB-REVIEW.md и этот файл: повторная проверка перед интеграцией и подготовленное описание PR.

Схемы и миграции сохранены без изменений. Рабочие конфигурации, пароли, ключи и данные клиентов не добавлены. Старый deployment ZIP не обновлён и не содержит исправлений этой ветки.

## Проверка перед PR

Повторно выполнены: 12 клиентских тестов, 12 PHP/DB/браузерных интеграционных тестов, 2 теста настоящего Apache — все PASS. PHP lint: 9 файлов; node --check: 3 файла; git diff --check: PASS. Локальный merge-tree с актуальным main не выявил конфликтов.

Среда: PHP 8.4.27, Apache 2.4.69, MariaDB 11.8.6, Chromium/Playwright. Точный MySQL 5.7 не проверен; production-функциональность не выводится из локальных результатов. Интеграция использует только временную копию и случайную loopback-БД neuro_test_*.

## Обязательный барьер перед слиянием

**Не сливать до подтверждения отсутствия production-публикации.** Существующий deploy.yml реагирует на push main для public/** и private/**. При DEPLOY_ENABLED=true merge может выполнить backup/rsync на production. Значение repository variable, результаты Actions и серверные настройки недоступны через текущий GitHub API (Forbidden). Нельзя считать deployment отключённым только потому, что основной workflow не изменён.

Сам PR не соответствует событиям запуска существующего deploy.yml: pull_request в нём нет. Это не проверка других внешних интеграций, настройки которых недоступны.

Перед merge требуется подтверждённое отключение автопубликации либо отдельное одобренное изменение workflow, исключающее автоматическую запись на production. Производственный деплой этим PR не разрешается. PR не должен закрывать задачу устранения production 503: точная серверная причина в этом этапе не установлена.
