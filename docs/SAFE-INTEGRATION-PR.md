# Stage 2.1: проверенные исправления и только ручная публикация

Ветка включает одобренные исправления Stage 2.1 и устраняет риск автоматической публикации после merge в main. Раньше push main мог выполнить backup/rsync при DEPLOY_ENABLED=true; теперь у deploy.yml нет автоматических событий запуска.

## Изменения

- Сохранены коммиты Stage 2.1: d688bca, 6d8c146, f3bdbd8; документационная проверка 78fb800.
- .github/workflows/deploy.yml: только workflow_dispatch, job только для refs/heads/main; dry_run по умолчанию true. Реальная публикация требует dry_run=false, явного ввода PUBLISH neurodelo.pro и прежнего DEPLOY_ENABLED=true. Проверка выполняется до checkout/SSH.
- Существующие SSH/secrets/host-key checks, приватный backup, исключения config.php и политики, concurrency, очистка ключей и rsync без --delete сохранены.
- tests/test_deploy_workflow.py: проверки ручных условий, ошибочных подтверждений, инъекции через ввод, shell-синтаксиса, dry-run без backup и с двумя rsync --dry-run; сохранения проверок SSH и исключений. SSH/rsync заменены локальными заглушками.

## Проверки

- actionlint 1.7.7: PASS для YAML/контекстов/выражений. ShellCheck/Pyflakes не запускались; bash -n для shell-шагов выполнен отдельно.
- 6 workflow-тестов, 12 клиентских, 12 интеграционных и 2 Apache-теста — PASS, 0 FAIL.
- PHP lint 9 файлов, JavaScript syntax 3 файла, git diff --check — PASS.
- PHP 8.4.27, Apache 2.4.69, MariaDB 11.8.6, Chromium. Точный MySQL 5.7 не запускался. Тесты приложения используют временную копию, синтетические данные и loopback-БД.

## Границы интеграции

Автопубликация отключена **в предлагаемой версии workflow** независимо от текущего DEPLOY_ENABLED. Пока PR не слит, main содержит прежний workflow; нельзя считать настройки main уже обновлёнными. После слияния сам push/merge не подходит под события новой версии. Сохранённый DEPLOY_ENABLED является дополнительным барьером, не автоматическим разрешением публикации.

Проверки workflow — локальные контракты/симуляция, не запуск GitHub Actions и не доказательство поведения внешних интеграций, которых нет в исходниках. Соединения с SpaceWeb и производственные операции не выполнялись. Схемы, миграции, рабочий config.php, пароли, политика и данные не менялись. Старый deployment ZIP не содержит исправлений и не обновлён.

PR подготовлен для просмотра и одобрения интеграции; не включать auto-merge. Одобрение интеграции не разрешает production deployment. Stage 2.2 будет отдельной веткой после одобрения этой интеграции: сохранение правок формы во время отправки, корректный первоначальный экран CRM, регрессия обоих случаев и дальнейший обзор workflow. Код Stage 2.2 в этот PR не включён.
